\begin{frame}{Question and setup}
\begin{itemize}
  \item \textbf{Clean data:} does adding an item memory to TIGER improve
        next-item recommendation (no poisoning, no unlearning)?
  \item \textbf{Poisoned data:} which part of the architecture gives the
        gain, does it survive unlearning, and where does the spam live?
  \item \textbf{Data:} Amazon Beauty, Sports, Toys (5-core, leave-last-out split).
  \item \textbf{Seeds:} 2, 3, 5, 7, 11.
  \item \textbf{Metrics:} test NDCG@10 (N@10), higher is better; on poisoned
        data also SH@10 (spam hit rate), lower is better.
\end{itemize}
\end{frame}

% ---------------------------------------------------------------------------
\begin{frame}{What the rows mean: model variants}
All variants share the same TIGER backbone (T5 encoder-decoder, 4 + 4 layers,
$d_{\text{model}}=128$, 4 semantic-ID tokens per item, beam search).
\medskip

\small
\begin{tabular}{@{}l p{0.78\linewidth}@{}}
\toprule
\textbf{plain}  & TIGER as is. The baseline. \\
\textbf{im}     & plain + \textbf{item memory}: one learned 128-d vector per
                  item, mapped by a small adapter and added to that item's
                  input token embeddings. Trained with memory dropout (10\%
                  null vector) and neighbor mixing (20\%, text-embedding kNN). \\
\textbf{imc}    & im + a \textbf{consistency} loss (KL, weight 0.1) that keeps
                  predictions with and without memory close. \\
\textbf{imfree} & im \textbf{without} dropout and neighbor mixing. Capacity
                  control: same extra parameters, no regularization. \\
\bottomrule
\end{tabular}
\end{frame}

% ---------------------------------------------------------------------------
\begin{frame}{What the columns mean: recipes and reporting}
\small
\begin{tabular}{@{}l p{0.76\linewidth}@{}}
\toprule
\textbf{\_es}     & Our repo recipe: Adam, lr $10^{-3}$, batch 1024, early
                    stopping on validation Recall@5 (patience 10 checks),
                    semantic IDs from our RQ-VAE. \\
\textbf{\_gp40rk} & GRID paper recipe: Adam, lr $5\cdot10^{-4}$, batch 256,
                    early stopping on validation N@10 with patience
                    \textbf{40} checks, semantic IDs from \textbf{RK}-Means. \\
\midrule
\textbf{mean}     & Mean test N@10 over finished seeds. \\
\textbf{gain}     & Paired gain vs.\ plain: per seed, (variant $-$ plain) / plain,
                    then averaged; only seeds where both finished. \\
\textbf{worst}    & Smallest per-seed gain (is it positive on every seed?). \\
\textbf{memory off} & Same trained model evaluated with the null vector in
                    place of every item's memory: how much the model leans
                    on the memory. \\
\bottomrule
\end{tabular}
\end{frame}

\begin{frame}{Poisoned data: the architecture ladder}
\small
\begin{tabular}{@{}l p{0.74\linewidth}@{}}
\toprule
\textbf{+ score}       & output-side item score $\langle h, W_{\text{out}} v_i\rangle$
                         from the same memory, trained with a sampled softmax,
                         used to rerank the beam. \\
\textbf{+ consistency} & the KL consistency loss of imc. \\
\textbf{score only}    & plain + the score head, no input memory (control:
                         is the gain just a reranker?). \\
\midrule
\textbf{setup}         & Beauty with 1\% bandwagon spam on one target item;
                         3 target strata (unpopular, mid, popular) $\times$ 5
                         data seeds = 15 cells; 4000 training steps. \\
\textbf{unlearning}    & full deletion of the fake users with F+R or NAU. \\
\textbf{SH@10}         & share of test users whose top 10 contains the spam
                         target. Lower is better. \\
\bottomrule
\end{tabular}
\end{frame}

\medskip
\begin{itemize}\footnotesize

        $p\le6\cdot10^{-4}$; consistency with memory off $p\le0.05$.

\begin{frame}{Plan: experiments}
\footnotesize
\begin{enumerate}
  \item \textbf{Second dataset (running):} the poisoned ablation on Toys,

        with the same statistics. Sports stays in the clean table only.
  \item \textbf{MUNKEY on the grid:} the architectural ``unlearning by
        design'' baseline, so far only on one cell (mid, seed 2). Rows:
        key deletion alone, key deletion + F+R, F+R, NAU.
  \item \textbf{Retrained references:} the gold standard for every cell;
        12 of 15 Beauty cells exist (plain, imsc); add the last 3 and Toys.
  \item \textbf{Generality (meeting 18.08):} a second attack (clone-inject,
        seed 2) on TIGER, + memory, + memory + score + consistency.
  \item \textbf{Privacy (meeting 31.07):} forget-only F+R (no retain data,
        no rehearsal) on a subset of cells; does the memory help there?
\end{enumerate}
\end{frame}

\begin{frame}{Plan: positioning and writing}
\footnotesize
\begin{itemize}
  \item \textbf{Story:} the architecture gives +15 to 21\% N@10 that
        survives unlearning; the spam lives in the backbone and unlearning
        removes it there (memory-off check); consistency = robustness.
        Do not overclaim the memory as the place where forgetting happens.
  \item \textbf{ComeIR (arXiv 2605.11447):} related work. Its memory is
        hashed and shared across items, so deletion cannot be localized;
        ours has one row per item. A ComeIR-style row is optional.
  \item \textbf{Main tables:} the architecture ablation (Beauty, Toys) with
        CIs and $p$-values; clean results on 3 datasets and 2 recipes;
        memory-off before / after unlearning.
  \item \textbf{Order:} Toys $\rightarrow$ MUNKEY $\rightarrow$ references
        $\rightarrow$ second attack $\rightarrow$ forget-only $\rightarrow$
        write; ComeIR row only if time allows.
\end{itemize}
\end{frame}

% ---------------------------------------------------------------------------
\begin{frame}{Takeaways}
\begin{itemize}
  \item Clean data: im and imc beat plain on all 3 datasets under both
        recipes. Strong on Beauty (+15 to 20\%) and Toys (+25\%), weak on
        Sports (+5 to 11\%, some seeds below plain).
  \item The gain is \textbf{not} extra capacity: imfree has the same
        parameters and is at or below plain (except Toys, +6.4\%).
  \item Poisoned data: the memory gives most of the gain (+15\%), the score
        adds 5 points. The score alone gives +8\%.
  \item Gains survive F+R and NAU; every architecture forgets the spam.
  \item Consistency adds no accuracy, but makes the model degrade more
        gracefully when the memory is missing.
  \item The spam lives in the backbone, not in the memory rows.
\end{itemize}
\end{frame}
